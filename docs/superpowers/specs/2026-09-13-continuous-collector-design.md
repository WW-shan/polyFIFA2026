# 连续体育盘口采集与可见的数据质量

依据用户确认的连续采集目标和本次“让它一直采集不同比赛、不同场次，并修正已有问题”的要求实施。现有短样本和代码测试不再作为已经收集齐全比赛的替代物。

## 工作范围

保留现有只读公共数据链路，不加载交易密钥、不下单、不推送远端。新增连续运行方式，持续发现网球和乒乓球比赛，按配置可增其他体育标签；不按价格、交易量、策略资格或最终赢家筛选。当前机器作为默认部署位置；外接盘／服务器可通过配置替换。默认保留 20 GiB 空闲空间，空间不足安全暂停，绝不自动删除旧原始数据。

## 三个独立交付单元

1. **不中断的只读归档。** 原始连接和 journal 持续运行。写入有序的 `collector/checkpoint_end` 边界后同步关闭当前分段，再开新段接着记录。只将已经封口的分段建立硬链接快照；快照是不可变输入，可交给既有尾窗导出器，不能把仍在写的文件当成完成数据。标明这是采集截止点，不是整个采集进程已经结束。
2. **连续采集管理。** 周期发现新场次、保留正在跟踪的比赛；元数据短暂消失或请求失败不当作比赛结束，也不将旧响应重新标成新数据。明确结束／关闭后继续保留已观察到的订阅十分钟，再退出该事件，其他比赛连接不受影响。已关闭 token 不再反复发无意义的 HTTP book 请求。完成场次有真实结束标签后，在独立子进程中排队导出，不能用 CPU 密集回放阻塞接收 WebSocket 的进程。
3. **运行入口与质量展示。** 提供本机后台服务的启动／停止／状态命令及仅绑定 `127.0.0.1` 的状态页。显示采集中、末段已结束待归档、归档完成、缺结束标签、连接或磁盘异常。盘口价格覆盖与比分新鲜度分别显示；价格完整但比分过旧仍可查看价格，不再统一写成“不可回放”。已关闭、窗外、实际缺失保持不同标签，不隐藏失败样本。

## 生命周期与持久化

- 新发现时记录首次观测、事件／game／market／token 身份和当前订阅；首次见到就已经结束的场次不能冒充完整采集。
- `endDate` 不参与实际终场判断。首次明确观察到结束的本地时间是保留期起点；不会被每次轮询重置。真实 `finishedTimestamp` 用来定位回放窗口，不把保留期起点混成真实终场。
- 终场标签晚到时保留原始响应；仅补边界，不回填较新的比分。已记录的盘口和成交继续沿用当前审计规则。
- 进程重启使用新 run 和连接代次；已有数据及每场来源运行引用保留。重启之间真实缺失不能伪装连续，跨重启窗口没有足够证据就标为不完整。
- 完成归档任务与失败任务存盘，重启可重试到新的输出目录；已有结果不覆盖。历史来源保存在磁盘，热状态和连接历史有数量边界。

## 本机运行保护

用户级 macOS 后台服务，异常退出可重启；不修改其他服务。状态页无下单接口，无任意文件读取／目录遍历能力。可配置保持空闲时不休眠，但关机、合盖、断网仍会中断；有缺口就记录。低磁盘空间暂停后，在空间恢复时以新 run 继续。原始数据不自动清理。

## 验收

除现有测试外，验证：A 完赛归档时 B 仍接收；下一轮新发现 C 并取得快照；目录或关联查询局部失败不误退订；同一个终场状态反复出现不会延后退订；封口后的快照不随继续写入而变化；导出不阻塞接收；崩溃后新 run、后台重启、低磁盘暂停／恢复、状态文件与本地页面可用。最后实际启动持续采集，检查真实新记录、订阅、心跳、HTTP 审计和状态入口，明确哪些比赛尚未录完。

不能承诺交易所绝不漏发，也不能在采集刚启动时把已经进行中的比赛补成完整历史。本次交付是实际持续运行的采集服务及诚实的完整性报告，不是保证每个已列出的盘口已经拥有完整历史。
